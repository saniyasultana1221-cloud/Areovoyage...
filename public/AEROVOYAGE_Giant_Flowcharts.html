3. Backend Database & Services Architecture

Supabase & Service Pipelines
LAYER 1 📦
Frontend Services
• destinationService.ts: Dynamic relational query engine.

• supabaseService.ts: Persists bookings & leads.

• stripeService.ts: Test card authorization (4242...).

• travelDataService.ts: Nominatim & Open-Meteo API.
TypeScript Services
LAYER 2 ⚡
High-Speed Cache
• In-Memory SWR Cache (5-Minute TTL): Returns 0ms instant data for repeated searches.

• Pre-seeded Local Fallback Repository: Provides 100% reliable offline data for Hyderabad, Rome, Tokyo, Agra, etc. if network is disconnected.
SWR & Offline Fallback
LAYER 3 ☁️
Cloud Backend & APIs
• Supabase PostgreSQL: Normalized tables (`destinations`, `destination_details`, `reservations`, `reviews`).

• Stripe Elements Sandbox: Test payments.

• OpenStreetMap Nominatim: Live geocoding.

• Open-Meteo: Real-time climate.
PostgreSQL & REST APIs

4. Supabase Relational Database Schema Table

PostgreSQL Relational Tables
Table Name Primary Key Foreign Keys & JSONB Fields Description & Purpose
destinations city_slug (VARCHAR PK) city_name, country, lat, lon, daily_rate, rating Primary catalog of worldwide luxury destinations.
destination_details id (UUID PK) city_slug (FK), landmarks (JSONB), itinerary_days (JSONB) Rich relational content for Hyderabad (Charminar, Golconda, Nizam Itineraries).
reservations id (AV-XXXX PK) user_email, full_name, dates, amount_paid, stripe_intent_id Confirmed guest booking records and lead capture persistence.
reviews id (UUID PK) city_id (FK), user_name, rating, comment, created_at Real-time user feedback with dynamic average rating recalculation.
